`v1.2.0` 是一次**评测正确性与口径诚实性**为主题的协议升级版本：formal evaluator 升级至 **0.7**，落地结构性失败口径闭环（D076），完成第二轮 Baseline 质量闭环（D075），并重新签署全部八个 RC 证据门。

---

### 一、 协议演进与评测口径

#### 1. formal evaluator 0.6 → 0.7：结构性失败口径闭环 (D076)
- **diagnose 与 score 资格判定对齐**：Gold 参考查询在 baseline 快照上被安全策略拒绝（如零贡献聚合 `AGGREGATION_TOO_SMALL`）的案例计入新增的 `excluded_cases` / `excluded_case_ids`，不再计为 Agent 失败；通过率分母改为 `total_cases - excluded_cases`；Markdown/HTML 诊断看板新增 Structural Exclusions 区块；
- **变体快照 Gold 可用性探针**：`evaluate_formal` 的 `_reference` 经真实执行网关探测 Gold 可用性——baseline 一律探测，baseline 资格内案例的变体逐快照探测；变体上 Gold 自身零贡献（如 C360_1284 在 seed43）记为 `applicable=False, policy_code=AGGREGATION_TOO_SMALL`，不再伪装成 Agent 回放失配；
- **版本纪律硬化**：`load_conformance` / `load_negative_control` / `load_score_inputs` 全部 fail-closed 要求 0.7 输入，`check_formal_release` 将 manifest 的 evaluator 版本纳入冻结检查；`DiagnosticSummary` 强制 `passed + failed + excluded == total` 守恒；旧 0.6 工件仍可读（Literal 拓宽）但永不升版。

#### 2. 第二轮 Baseline 质量闭环 (D075)
- 基于失败归因矩阵修复 6 类 Agent 侧根因：客户姓名/幸福指数拒答识别（对齐题包 accepted reason codes）、业务名逐字最长匹配指标裁决、PIT 无显式日期澄清、metric 槽位澄清、服务关系 `is_primary` 极性解析、复合关联多余谓词移除；
- LocalModelAdapter 回环（human 20）经确定性解析器同步从 15 → 17。

#### 3. 评测结果（evaluator 0.7，官方 baseline）
- **Public Dev 120**：108 通过 / 0 失败 / 12 结构性排除，合格分母 108，**加权 1.0**（五维全满分）；
- **Private Hidden 100**：86 通过 / 4 失败 / 10 结构性排除，合格分母 90，**加权 0.9784**（correctness 0.958，robustness 0.946，其余满分）；
- **负对照**：`--agent wrong` 在合格分母上 0/108 得分；
- 仅剩的 4 个隐藏失败与 0 个公开失败均为真实 Agent 语义缺口，无任何结构性误计。

## English Version

**Release**: `v1.2.0`  
**Date**: 2026-10-24  
**Git Tag**: `v1.2.0`  
**License**: [Apache-2.0](LICENSE)  
**Ranking**: Permanently disabled (`ranking_enabled=false`)

`v1.2.0` is a protocol-upgrade release focused on **evaluation correctness and accounting honesty**: formal evaluator is upgraded to **0.7** with the structural-failure accounting closure (D076), the second baseline quality loop (D075), and all eight RC evidence gates re-signed.

### Key Highlights
- **Structural failure accounting (D076)**: `c360 diagnose` now aligns with the `score` eligibility rule — cases whose Gold reference is policy-rejected on the baseline snapshot are reported as `excluded_cases` instead of agent failures, with the pass-rate denominator becoming `total_cases - excluded_cases` and dedicated Structural Exclusions dashboard sections; `evaluate_formal` probes Gold applicability through the real execution gateway on the baseline and on variants of baseline-eligible cases (C360_1284-class zero-contribution variants no longer masquerade as agent mismatches); the evidence chain (conformance, negative control, score inputs, manifest) fail-closes on non-0.7 inputs and `DiagnosticSummary` enforces count conservation.
- **Baseline quality loop (D075)**: six agent-side root causes fixed — PII/happiness-index refusal detection, longest-verbatim business-name metric arbitration, point-in-time and missing-metric clarifications, service-relation `is_primary` polarity parsing, composite-join predicate cleanup; the local-model loop improved from 15/20 to 17/20.
- **Acceptance results (evaluator 0.7)**: Public Dev 120 — 108 passed / 0 failed / 12 structural exclusions, weighted **1.0**; Private Hidden 100 — 86 passed / 4 failed / 10 structural exclusions, weighted **0.9784**; negative control scores 0 on eligible cases; every remaining failure is a genuine agent semantic gap.
- **RC evidence**: all eight gates re-signed on evaluator 0.7, including a read-only / no-network / non-root (`uid 10001`) Docker runtime smoke and byte-identical reproducible builds.
