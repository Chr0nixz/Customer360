Customer360 Agent Benchmark 是一套面向金融高价值业务场景的可复现、可审计、默认安全执行的智能问数 Agent 基准测试平台。`v1.1.0` 是继基础底座之后的首个重大正式发行版本，标志着项目从基础问数原型演进为具备抗干扰多轮交互、受控计划校验、跨引擎方言转译、100 题稳定性隐藏集以及本地离线大模型适配的完备评测基准。

---

### 一、 核心特性与协议演进

#### 1. 多轮反事实澄清与抗干扰协议 (v1.1)
- **多轮状态跟踪**：`AgentRequest` 升级为 `protocol_version: "1.1"`，消息结构引入 `Message.turn` 轮次追踪；
- **反事实噪声注入**：`SlotReply` 扩充 `distractor` 与角色标签（`noise` / `counterfactual` / `irrelevant`），模拟真实交互场景中的背景叙述与干扰信息；
- **过度追问防御**：评测引擎对槽位已补齐后的多余追问判罚 `CLARIFICATION_FAILURE`，强制设立 `MAX_CLARIFICATION_TURNS = 4` 交互轮次上限防御。

#### 2. 受控逻辑计划校验引擎与元数据治理 (v1.2)
- **前置逻辑计划预检**：落地 `validate_query_plan` 工具，包含 9 类稳定拒绝码与 `INVALID_PLAN_SCHEMA` 优雅降级；
- **指标生命周期管控**：`MetricDef` 引入生命周期约束（`deprecation_date >= effective_date`），废弃指标拒绝时自动返回 `replaced_by` 替代指引；
- **拓扑闭包审计**：`c360 audit-metadata` 覆盖全量 9 张核心表外键与引用拓扑闭包校验，0 孤立引用。

#### 3. 跨引擎方言转译与四阶段性能采样 (v1.3)
- **语句级只读 AST 转译**：`transpile_sql` 采用语句级 AST 解析，杜绝字符串内分号误杀，严格拦截 ALTER/TRUNCATE/MERGE/GRANT/REVOKE/SET 等非只读操作；
- **PostgreSQL 活体容器等价集成**：`PostgreSQLExecutionGateway` 默认 Fail-Closed 准入隔离；CI 自动化集成真实 `postgres:16-alpine` 容器服务，DuckDB 与 PostgreSQL 多重集 100% 等价吻合；
- **四阶段性能度量模型**：`QueryReceipt` 透传端到端阶段耗时（`plan_ms` / `guard_ms` / `exec_ms` / `e2e_ms` 及 P50/P90/P95/P99 分位数），资源开销度量与正确性分数严格解耦。

#### 4. 发布完整性防篡改与 Dev 题包分层重构 (WP-01~07)
- **防篡改动态校验**：`check_formal_release` 动态重算全部公开制品 SHA256 摘要，双向 1:1 核对物理文件，拦截软链接与 `..` 路径穿越；
- **Dev 120 题全指标覆盖**：公开 300 题落地 240/36/24 配额（Train 150/18/12，Dev 90/18/12）；Dev 120 题达成 30 个指标全覆盖（各 ≥2 family）、5 条可执行 Join 路径全覆盖（各 ≥3 题），Train 与 Dev 之间严格 Family 隔离。

#### 5. 隐藏评测集扩容至 100 题稳定性目标 (D064)
- **独立候选池储备**：基于阻断 320 个公共 Family 后的 313 个独立语义 Family 储备完成扩容；
- **科学分层配额**：落地 61 Answer / 23 Clarification / 16 Refusal 黄金配额，覆盖 26 个独立业务指标与全部 8 类强制错误；
- **独立 Oracle 交叉校验**：61 道 Answer 题在隔离 Tiny 数据集上 100% 匹配独立 Python Oracle，改写槽位 0 漂移。

#### 6. 本地离线大模型适配器落地 (D065)
- **OpenAI 兼容端点适配**：实现 `LocalModelAdapter` 与 `create_local_model_agent`，无缝接入本地 Ollama / vLLM / llama.cpp；
- **严格回环网络防御**：`assert_local_endpoint` 仅放行 `localhost`/`127.0.0.1`，严格拦截外部公网连接；引入 `SafeLocalRedirectHandler` 拦截 30x 重定向 SSRF 穿透；
- **前置单客 ID 清洗**：解析意图阶段主动剔除 `customer_id` 分组列，防止单客隐私泄露；
- **CLI 原生支持**：CLI 与矩阵评测支持 `--agent local-model`。

### 二、 评测可信与安全红线

1. **单条只读 SQL**：严禁 DDL、DML、DCL 或多语句注入；
2. **单客 ID 分组强防御**：单客 ID 严禁作为 GROUP BY 维度，最小组贡献人数强制防御（`min_group_size`）；
3. **真值不依赖 LLM**：严禁使用 LLM 作为 Gold SQL、Gold Answer 或裁判，评测基于确定性多重集比对；
4. **官方准入引擎不变**：DuckDB 保持官方正式评测唯一准入引擎，PostgreSQL 网关默认 `admitted=False`；
5. **公私物理隔离**：公开 Dev 与隐藏 Private 独立出分，禁止在线排名。

Customer360 Agent Benchmark is an offline, reproducible, secure-by-default enterprise agent benchmark designed for high-value financial data intelligence. `v1.1.0` represents our first major formal release following foundational stabilization, incorporating counterfactual multi-turn protocols, controlled query plan validation, cross-engine transpilation, a 100-case hidden stability benchmark, and local offline LLM adaptation.

### Key Highlights & Protocol Evolutions
- **v1.1 Multi-Turn Dynamic Clarification**: Protocol version 1.1, turn tracking via `Message.turn`, distractor noise injection via `SlotReply.distractor`, over-clarification guards, and `MAX_CLARIFICATION_TURNS = 4` turn limits.
- **v1.2 Query Plan Validation & Metadata Lifecycle**: Pre-execution plan validation with `validate_query_plan` (9 stable rejection codes, `INVALID_PLAN_SCHEMA` graceful handling), metric chronological lifecycle constraints (`deprecation_date >= effective_date`), and full foreign key referential integrity closure auditing in `c360 audit-metadata`.
- **v1.3 Cross-Engine Adaptation & Phase Performance**: Statement-level AST transpilation in `transpile_sql` with strict read-only enforcement, PostgreSQL fail-closed isolation with live `postgres:16-alpine` container integration, and 4-phase execution timing profiling (`plan_ms`/`guard_ms`/`exec_ms`/`e2e_ms`).
- **WP-01~07 Release Integrity & Stratified Dev**: SHA256 dynamic re-verification and path traversal defenses; 300-case 240/36/24 quota re-allocation (Train 150/18/12, Dev 90/18/12) achieving 30/30 metric and 5/5 join path coverage in Dev 120 with strict family isolation.
- **Hidden Benchmark 100-Case Expansion (D064)**: 100 independent cases (61 Answer / 23 Clarify / 16 Refusal) covering 26 distinct metrics and 100% of 8 required error classes, verified with 100% independent Python oracle parity on isolated Tiny data.
- **Local Offline LLM Adapter (D065)**: Native integration with Ollama/vLLM/llama.cpp via `LocalModelAdapter` and `--agent local-model`; strict loopback whitelisting (`localhost`, `127.0.0.1`), SSRF redirect defenses, and pre-execution customer ID group-by stripping.
